# Outcome-Based Roadmaps & Release Plan Prompts

**Source:** authored for this library. Not yet in the Productside Playbook. This Play is Template 17 of 24 in the B2B work-in-progress deck (slides 78-80), which has no AI page for it. The prompt follows the style of the deck's own AI prompts and apply its global rule.

This is a copy-paste prompt for working this Play in any chat-based AI tool. You don't need this skill installed to use it. If the skill *is* installed, it already behaves this way.

The Playbook's rule for every AI page: **you do the thinking, and AI pressure-tests it.**

## How AI Supports This Play

AI works here as a critic of the roadmap the PM drafted. It checks that each horizon holds outcomes, not outputs; that items sit in Now, Next, or Later by confidence; that each output links to an outcome; and that discovery work appears alongside delivery. The placements and the sequence stay with the PM and their team.

| Use AI when | Avoid AI when |
|---|---|
| The PM has an outcome tree and a draft roadmap, and wants it pressure-tested before sharing it. | The request is to produce a dated feature roadmap, or to place items without the PM's evidence about confidence. |

**Outputs to expect:** outputs posing as outcomes flagged, each placement questioned against the evidence behind it, and links from outputs to outcomes checked.

## Common Trap

**A Feature List Dressed as an Outcome Roadmap.** The roadmap's Now column lists "SSO," "mobile app," and "reporting v2," with an outcome heading added on top. The team is back in the build trap, with outcome language as decoration. Executives and engineering read it as a feature commitment.
