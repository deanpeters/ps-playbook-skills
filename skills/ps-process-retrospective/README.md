# ps-process-retrospective

Productside Process Retrospective skill (Template 24 of 24 in the B2B work-in-progress deck; Template 23 in the baseline).

## Files

- `SKILL.md` - skill definition, key concepts, application steps, pitfalls
- `template.md` - left sidebar (administrative) and four-quadrant canvas scaffold
- `prompts/` - copy-paste prompt for chat-based AI tools (authored for this library; the deck has no AI page for this Play)
  - `README.md` - how AI supports this Play, the common trap, how to run the prompt
  - `01-prepare-and-close-retro.md` - prepare and close out your retrospective
- `examples/sample.md` - strong, weak, and drift-bug examples with commentary
- `assets/ps_process_retrospective_playbook_pages.pdf` - source pages from the canonical playbook

## Notes

- Skill name uses the `ps-` prefix per project convention.
- This skill belongs to the **Deliver** phase.
- This is a **process skill** (`type: process`), not a component skill. The agent sets up the session and documents the results. The team runs the actual retrospective.
- Evidence gathering: **neither** - no web research and no upstream artifacts are required. This is an internal team reflection exercise.
- No tech-role bias guard applies here. Step 1 instead confirms the scope and timeframe of the retro.
- Psychological safety is the prerequisite. If the Anchors quadrant is empty or vague, the retro has not worked.
- Action items with owners and dates are the primary deliverable. A retro without them is just a meeting.
- Downstream: ps-risk-assessment - significant Barriers identified in the retro may warrant formal risk planning.
