# ps-outcome-strategy-discussion

Productside Playbook Template 01: Outcome & Strategy: Guided Discussion.

## Files

- `SKILL.md` - skill definition, key concepts, application steps, pitfalls, and references
- `template.md` - working scaffold for the discussion guide and outcome summary
- `prompts/` - copy-paste prompt for chat-based AI tools (authored for this library; the deck has no AI page for this Play)
  - `README.md` - how AI supports this Play, the common trap, how to run the prompt
  - `01-prepare-discussion-guide.md` - prepare your guided discussion
- `examples/sample.md` - strong, weak, and drift-bug examples with commentary
- `assets/ps_outcome_strategy_discussion_playbook_pages.pdf` - source pages from the canonical playbook (pages 4-6: overview, example, blank)

## Skill type

Process. This skill helps a PM prepare for and document a facilitated conversation. It does not produce a research artifact or a component for a deck. It produces a shared written record of alignment reached.

## Where it sits in the playbook workflow

This is the first play in the Productside Playbook. It runs before any discovery work begins.

The output of this play - a clear, agreed business outcome - is the input for the plays that follow:

- **ps-outcome-tree** (Template 03): takes the business outcome established here and connects it to product outcomes and metrics
- **ps-jobs-to-be-done**: starts from the customer identified during this discussion

## Agent role note

The agent supports two phases of this play:

1. **Before the conversation:** prepare the discussion guide, surface PM assumptions, flag visible gaps
2. **After the conversation:** help structure the outcome summary, identify gaps, draft the KDP call

The conversation itself is PM-owned. The agent cannot participate in a live discussion with a manager or sponsor. If the PM asks the agent to generate what the manager "probably said," redirect: the discussion must happen with a real person who has the strategic context the agent does not have.
